# Custom monster attributes (API 16): a monster effect's attribute filter
# goes past 127 (ATTRIBUTES_MAX 255), so MonsterEffect's `attribute` and
# `each_attribute` widened from signed char to short. Both grew in place,
# into the byte clang already padded them to for the field after (`card`,
# then the struct's own trailing pad): every other field keeps its offset,
# and sizeof/align are unchanged (20, 4, both builds). A v0.3.0 mod only
# reads these through Cards_MonsterEffects's `const MonsterEffect *` (the
# SDK has no call a mod can use to write one of the engine's own), and a
# narrow signed-char read of the new short's low byte, little-endian, still
# gives -1 or 0-127 exactly as before; a value of 128-255 is new and no
# v0.3.0 mod could have compiled a comparison against one. Same reasoning
# as DuelResultDisplayState's starchip_prize above.
accept v0.3.0 record MonsterEffect widened attribute and each_attribute into their own trailing pad byte
